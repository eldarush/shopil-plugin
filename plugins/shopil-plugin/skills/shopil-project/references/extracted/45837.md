חלק ה חומרי הגשה והסבר 5 נקודות

1. קוד וקלטים. הגישו תיקייה דחוסה או קישור למאגר עם קובצי המטלה שהשלמתם, שכבת השליפה, ממשק הצ׳אט, הנחיות שני המודלים וקלטי הניסויים. ציינו בבירור אילו רכיבים נלקחו מפרויקטי הקורס ומה פיתחתם בעצמכם.

2. הוראות הרצה. צרפו README עם סביבת Python והתלויות, הכנת נתוני ה־ETL, הפעלת שני מצבי הזרם, הפעלת הצ׳אט והרצת הבדיקות. אפשר לעבוד ב־Windows עם Cursor ו־uv כפי שנלמד. כללו קובץ דוגמה לשמות משתני הסביבה, ללא מפתחות גישה.

3. תוצרי בדיקה. צרפו את פלט בדיקות dbt ובודקי התרגיל, דוח טעינה וניקוי, חלונות ופלטי צד, מדדי קליטה והקבצות, דוח ההתאמה ויומני Actor ו־Critic. צרפו צילומי מסך של קליטה פעילה ושל תשובה עם מקור ומועד נתונים.

4. דוח קצר. הגישו עד שלושה עמודי הסבר, מלבד תרשים ותוצאות. הסבירו את מדיניות הטעינה, את ההבדל בין קבוצה לחלון, את תפקידי Watermark ו־Grace, ואת ההגנה מפני ספירה כפולה. תארו כיצד משוב המעריך תיקן תשובה ומה בדקתם ידנית.

5. תרשים המימוש. הציגו את הארכיטקטורה שבניתם, כולל נתוני המקור, היעדים, שכבת הראיות וקשת המשוב. ציינו היכן נשמר checkpoint, מה גבול הטרנזקציה והיכן נוצר צילום המצב המשמש לשאלה.

גבולות המימוש והרחבות רשות

החובה מתבססת על המנוע המקומי ושמירה ב־SQLite. כל אירוע שומר את המזהים, המונים, החלונות, פלטי הצד ו־checkpoint באותה טרנזקציה. שמירה מקומית זו אינה מוכיחה מסירה בדיוק פעם אחת של הודעה חיצונית.

לאחר השלמת החובה אפשר להרחיב לחיפוש ביקורות ב־LanceDB, לתזמור ב־Dagster, למתווך Redpanda או לניסוי קריסה לפני ואחרי Commit. אלה מסלולי רשות מהמצגות, ואינם תנאי לקבלת מלוא הניקוד.
