### Speaker notes

קוראים כל מסלול מימין לשמאל. במסלול המובנה dlt טוען לקוחות, הזמנות ומוצרים לשכבת raw בתוך DuckDB. dbt בונה באותו מחסן את שכבת staging ואת טבלאות marts, ומפעיל בדיקות. דוחות וניתוח צורכים את התוצרים. במסלול הידע קוראים מסמכי Markdown, מחלקים לקטעים, יוצרים וקטורים ושומרים ב-LanceDB טקסט, וקטור ופרטי מקור. החיפוש משתמש בטבלה המוכנה ומחזיר קטעים ומקורות. מסגרת Dagster מקיפה את הכנת הנכסים ואת עדכונם; היא אינה טוענת שפעולת החיפוש או יצירת תשובת LLM מופעלות על ידו בפרויקט. תרגיל הביקורות מוסיף קליטה, ניקוי, מדדים ווקטורים לביקורות. נכסי Dagster נפרדים למסלול הביקורות הם הרחבה אפשרית. תהליך Python הידני קודם לארכיטקטורה זו כהדגמת יסודות, ויצירת תשובת LLM לאחר החיפוש היא אפשרות נפרדת.

שאלה לכיתה: היכן נמצאות שכבות raw, staging ו-marts, ומה Dagster מפעיל?

תשובה מוצעת: שלוש השכבות נמצאות ב-DuckDB. Dagster מפעיל את נכסי הטעינה, מודלי dbt ועדכון טבלת הידע לפי התלויות.
